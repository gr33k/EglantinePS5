## Why a one-file patch is unsafe

1. The deconstructed loader's `IsRomFSUpdatable()` returns false. Merely selecting update `exefs/main` would load its adjacent RomFS as a standalone loose title, even though the NUP marks the update non-standalone and 47 base paths are absent from it. This cannot establish correct base-plus-update semantics.
2. `Service::AOC::AccumulateAOCTitleIDs` lists `TitleType::AOC`/`ContentRecordType::Data` entries only when `GetEntry(...)->GetStatus()` succeeds. `ManualContentProvider::GetEntry` and `PatchManager` wrap entries as NCAs. Raw extracted add-on RomFS cannot pass as an NCA.
3. `RomFSFactory::Open` and `FSP_SRV::OpenDataStorageByDataId` reach AOC storage through NCA-backed `GetEntry`/`OpenRomFS`. Registering an ID without supplying a real, separately mountable RomFS would tell the guest DLC exists and then fail when it opens it. Overlaying DLC files into the base RomFS does not preserve separate AOC identity or guest mount semantics.

These seams span frontend selection, a core content provider, the deconstructed loader/patch manager, AOC enumeration, and filesystem storage. Do not bypass them by renaming the NUP, treating the non-standalone update as standalone, or copying add-on files into base. Do not mutate emulator source on this branch until a complete interface design and bounded host proof exist.

## Proposed narrowest safe implementation sequence

1. **Input receipt:** Deep-verify the isolated NUP copy and establish full identity of the root file before using the root as a source. Build immutable per-package manifests with exact title IDs, raw/display versions, file counts/bytes and SHA-256 of every extracted file. Extract the AOC only into a new isolated NAS path under a named low-priority job when I/O allows; never touch the root NUP or Aquinas inputs. Preflight no symlinks, hardlinks, traversals, unexpected files or nonregular entries. Keep the physical base tree and save data separate.
2. **Manifest gate:** Define one versioned Wonder-only manifest/receipt naming base `010015100B514000`, update revision 327680 for the same ID and AOC `010015100B515001`, plus verified file hashes. Parse the update NPDM ACI0 title ID and verify the AOC's base relationship (`GetBaseTitleID(010015100B515001) == 010015100B514000`). Fail closed to base/no AOC if the receipt, title ID, version, path, file type, size or SHA differs. Bind validation to opened no-follow descriptors and stable identity before/after hashing; do not trust a path-only check.
3. **Core representation:** Add an explicit validated loose-content representation to the core content-provider interface, separate from NCA entries. It must expose update ExeFS and a base-plus-update RomFS according to the NUP's layering semantics, and expose AOC Data as a separate RomFS by title ID. Adapt `PatchManager`, `RomFSFactory`/`FSP_SRV::OpenDataStorageByDataId`, and AOC enumeration to consume that type only after the manifest gate. Do not forge an NCA status or publish an AOC ID before its mount path is functional.
4. **Host contract before target build:** Prove valid base+update selects the verified update code and merged RomFS; AOC count/list reports exactly `010015100B515001` and opening its Data storage returns the verified AOC RomFS. Prove wrong SHA, NPDM/title ID, revision, missing/extra files, symlink/hardlink, stale receipt and interrupted read all fall back to base with zero AOC. Prove an unrelated base title and a base-only Wonder launch remain unchanged. Test the same code path used by PS5, not only a model of it.
5. **Release boundary:** After host proof, build/sign a distinct provider from this branch in its own object bank. Compose with the *then-current* safe-menu branch; do not install one binary over the other. Pin the exact live preimage, neighbors and rollback in a guarded one-file transaction. Parent alone performs a fresh-boot PS5 test of update-owned frames/version, AOC visibility and guest access, gameplay/input/audio/save, safe menu Resume and same-row Return. No physical qualification follows from source or host tests.
